# 设计完成后各阶段工期透明规范

## 核心原则

需**多次向客户明确**设计结束之后各阶段的预估时间，避免客户误以为"设计稿画完 = 网站马上上线"。

## 必须向客户说明的三个阶段

| 阶段 | 说明 |
|------|------|
| 开发时间 | 前端页面开发、后端功能对接的预估工期 |
| 测试时间 | 功能测试、兼容性测试、内容审查的预估工期 |
| 数据添加时间 | 产品/新闻等内容录入、SEO 数据配置的预估时间 |

## 沟通节点

| 节点 | 动作 |
|------|------|
| 设计定稿时 | 第一次告知：设计完成后还有开发→测试→数据三个环节 |
| 设计交付时 | 第二次告知：重申各环节预估时间 |
| 关键里程碑 | 每完成一个阶段，同步更新后续时间 |

## 注意事项

- 客户往往只关注"设计稿什么时候画完"，忽略了后端的开发和测试
- 多次说明的目的是**管理客户预期**，避免因时间误解产生纠纷
- 每次说明建议以邮件形式保留记录，口头沟通后补一封确认邮件

## 适用场景

适用于所有网站设计项目中，设计稿定稿/交付前后向客户同步整体项目排期的场景。
