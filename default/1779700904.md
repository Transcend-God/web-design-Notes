# 设计稿向开发交接规范

## 核心原则

设计定稿后，需按统一标准将设计稿、标注、切图、源文件交付给开发，确保开发还原度。

## 交付清单

| 交付物 | 要求 | 说明 |
|--------|------|------|
| 设计稿链接 | 标注工具链接（蓝湖/摹客/即时设计等） | 给开发查看标注和切图 |
| 切图资源 | 按页面分文件夹，命名统一 | 不含设计源文件 |
| 设计源文件 | Figma/Sketch/PSD 等原始文件 | 用于后续修改 |
| 设计规范说明 | 字体、字号、颜色、间距的汇总表 | 开发参考 |
| 交互说明 | 动效、悬停态、过渡效果描述 | 非必选项 |

## 切图命名规则

```
[模块]_[元素]_[状态].[格式]

示例：
banner_title.png        → Banner 标题图
btn_submit_hover.png    → 提交按钮悬停态
icon_search.svg         → 搜索图标
```

## 切图格式选择

| 类型 | 推荐格式 | 原因 |
|------|---------|------|
| 图标/Logo | SVG | 矢量无损，体积小 |
| 普通图片 | PNG（无透明就 JPG） | PNG 保留透明通道 |
| 照片/Banner | JPG（质量 80%） | 平衡画质与加载速度 |
| 动效 | GIF 或 Lottie JSON | 交给开发评估 |

## 标注要求

| 标注项 | 必须标注 |
|--------|---------|
| 模块间距 | ✅ |
| 文字字号/行高/颜色 | ✅ |
| 按钮尺寸/圆角 | ✅ |
| 图片尺寸 | ✅ |
| 响应式变化规则 | 非必须，但强烈建议 |

## 交接流程

1. 设计定稿 → 上传标注工具 → 导出切图
2. 整理源文件到项目文件夹
3. 发送交接邮件给开发（附链接 + 切图压缩包）
4. 开发确认可执行 → 交接完成

## 注意事项

- 切图不要混在源文件里，单独打包
- 标注工具中的颜色统一用 HEX 或 RGBA，不要混用
- 交接邮件抄送 PM，留档备查

## 适用场景

适用于所有网页设计项目中设计师向开发交接的环节。
