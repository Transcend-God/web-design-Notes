# 复杂排版用图片替代——何时该用、代价与最佳实践

## 核心规范

**原则**：特别复杂的排版，尤其是偏向平面设计（Graphic Design）风格的复杂布局，直接做成图片，不要用 CSS 硬写。

## 一、判断标准

| 条件 | 做图片 | 用 CSS |
|---|---|---|
| 文字有复杂变形/扭曲/路径排列 | ✅ | ❌ CSS 做不到 |
| 多层不规则叠加 + 透明度混合 | ✅ | ❌ 各浏览器渲染不一致 |
| 装饰性文字（非正文，纯视觉） | ✅ | ⚠️ 可用但麻烦 |
| **正文内容**（需 SEO / 可选中 / 可翻译） | ❌ | ✅ |
| 需要响应式缩放的内容 | ❌ | ✅ |
| 频繁变更的文字（价格/日期/动态数据） | ❌ | ✅ |
| 标准排版（标题+段落+图片+网格） | ❌ | ✅ |

## 二、适合做图片的典型场景

| 场景 | 示例 | 原因 |
|---|---|---|
| KV / 主视觉区 | 首页大 Banner、活动主图 | 平面感强，文字做进图里更出效果 |
| 复杂数据可视化 | 信息图、时间轴、流程图 | CSS 布局难以精确对齐且响应式灾难 |
| 杂志风排版 | 文字环绕不规则图形、多栏交错 | CSS shape-outside 兼容差，不如图片稳 |
| 装饰性标题 | 立体字、金属质感、渐变描边 | CSS text-shadow/clip 能做但效果打折 |
| 表格/价格对比的"设计稿" | 报价方案展示图 | 客户要的就是视觉冲击，不是交互 |
| 邀请函/证书/名片 | 线上展示版 | 本质是平面设计产物 |

## 三、代价——必须知道

| 代价 | 说明 | 缓解方案 |
|---|---|---|
| **SEO 0分** | 图片里的文字搜索引擎读不到 | 同时写在 `alt` 属性里；关键信息另放 HTML 中 |
| **不可选中/复制** | 用户无法复制文字 | 非正文装饰无所谓；正文必须额外处理 |
| **响应式麻烦** | 图片缩放后文字可能太小 | 用 `srcset` + 多尺寸切图；或用 SVG（矢量） |
| **加载体积** | 比纯 CSS 大 | WebP 格式 + 压缩 + lazy loading |
| **修改成本** | 改一个字 = 重新出图 | 排版阶段就定稿，避免频繁修改 |
| **多语言** | 每种语言单独切图 | 成本高，不适合多语言站 |

## 四、最佳实践

1. **正文永远不要做进图片**：标题/装饰性文字可以，文章段落绝对不行
2. **优先考虑 SVG**：纯矢量排版场景用 SVG 替代位图，可缩放、体积小、文字可选中
3. **图片格式选择**：位图用 WebP（带 JPEG 降级），矢量用 SVG，动效用 APNG 或 Lottie
4. **alt 属性必须写**：图片里的关键文字信息全部写进 alt
5. **跟客户提前说清楚**：定稿后的图修改有成本，排版阶段的多次修改算设计迭代，不算额外工时
6. **切图命名规范**：`section-name@2x.webp`，含倍率和格式，方便后续维护

## 注意事项

- 分辨"排版复杂"和"形式花哨"：前者是项目真实需求，后者可能是客户不懂想瞎搞，要区分对待
- 交互元素（按钮/表单/链接）永远不要做进图片，否则后续任何修改都是灾难
- 如果页面有 5 张以上的大篇幅图片排版，要考虑首屏加载性能，做懒加载

## 适用场景

- 企业官网 KV 区、活动专题页、品牌形象页
- 平面感强的设计稿落地时，评估哪些模块需要用图片
- 跟开发交接时，明确标注"此模块用图片实现"
